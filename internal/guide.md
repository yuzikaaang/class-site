## 2. 凭据管理：Gitee access token 轮换

### 2.1 先别急着换——判断你还要不要 token

现在推送走的是 **SSH**，不是 token。所以先确认有没有别的地方在用它：

| 检查项 | 在哪看 | 结论 |
|---|---|---|
| 仓库推送 | 本地 `git remote -v` 显示 `git@gitee.com:...` | 走 SSH，**不需要 token** |
| Gitee 镜像同步到 GitHub | Gitee 仓库「管理 → 仓库镜像管理」里填的认证方式 | 这里用的是 **GitHub** 的 token，不是 Gitee 的 |
| 其他脚本 / 工具 | 你自己写过什么自动化吗 | 没有的话就不需要 |

**结论：如果你只是维护这个站点，那个 Gitee token 已经没用了 —— 直接删掉最省事。**

### 2.2 情况 A：直接删掉（推荐）

1. 登录 Gitee，点头像 → **设置** → 左侧 **安全设置** → **私人令牌**
   （直达：`https://gitee.com/profile/personal_access_tokens`）
2. 在列表里找到你当初建的那个令牌（创建于 2026-08 前后）
3. 点右侧 **删除** → 确认

> **删完要验证一下推送还正常**：让 AI 随便推个小改动（比如改个标点），或者直接看下一次正常改需求时有没有报错。
> 因为推送走 SSH，删 token **不会影响推送**。

### 2.3 情况 B：确实还需要 token → 新建并替换

1. 打开同一个页面：`https://gitee.com/profile/personal_access_tokens`
2. 点 **生成新令牌**
3. 描述随便填，比如 `class-site-2026-08`
4. **权限勾选：只勾需要的。** 单纯推代码勾 **`projects`（仓库读写）** 就够，**不要全选**——尤其别勾 `删除仓库` 之类危险的
5. 点提交 → **立刻复制那串令牌**（关掉页面就再也看不到了，只能重建）
6. 把**旧的那条删除**
7. 如果哪处配置里写了旧 token，换成新的

### 2.4 顺手清理：沙箱用的 SSH 公钥

之前 AI 的沙箱环境往你账号上加过一条公钥，**那条 key 的私钥在沙箱里，沙箱回收后就没人用了，留着是个多余入口**：

1. 打开 `https://gitee.com/profile/sshkeys`
2. 找 title 为 **`class-site-sandbox-20260829`** 的那条
3. 点 **删除**

> ⚠️ **删之前先确认当前 AI 环境还能正常推送**。如果删完 AI 说推不上去了，说明它还在用这条 key —— 让它重新生成一对密钥，把**新的公钥**加回来即可（不影响仓库内容）。

### 2.5 万一删错了怎么办

| 误删的东西 | 后果 | 怎么救 |
|---|---|---|
| SSH 公钥 | AI 推不了代码 | 让 AI 重新 `ssh-keygen` → 把新公钥加到 `https://gitee.com/profile/sshkeys` |
| access token | 用到 token 的地方失效 | 重新生成一个（见 2.3），**旧 token 无法恢复，只能重建** |
| GitHub 的 token（镜像同步用） | 主链不再自动更新 | 去 GitHub 重建 token，回 Gitee「仓库镜像管理」里更新认证 |

**仓库代码本身不会丢** —— 令牌和密钥都只是「开门的钥匙」，删了不影响仓库里的内容。

## 3. 接入一个新的 AI

这是本文件最值钱的一节。换 AI 时你最烦的就是「重新交代一遍」，照下面做就行。

### 3.1 三条原则

1. **给权限，不给密码。** AI 需要的是「能推代码」，不是「能登录你的账号」。推代码用 SSH 公钥就够了。
2. **先让它读文档，再让它动手。** 新 AI 最大的问题不是能力，是**没有上下文**。不读 `internal/notes.md` 就动手，等于让一个刚来的同学改你们班的规矩。
3. **要求它区分「验过」和「没验过」。** AI 很容易含糊地说「已完成」，实际有些东西它压根访问不到（比如本环境连不上 GitHub）。

### 3.2 权限分档（可以把这张表直接发给新 AI）

| 档位 | 事项 | AI 该怎么做 |
|---|---|---|
| 🟢 **可直接做** | 改代码、跑测试、`commit + push` 到 Gitee、重新发布备用链接、改 `internal/` 里的文档 | 做完报告即可，不用先问 |
| 🟡 **做完要说明** | 改站内公告文案、改站规/铁律、动学生数据（清空排期、删券记录）、改对外可见的链接 | 可以做，但必须明确列出改了什么、影响谁 |
| 🔴 **必须先问** | 动你的账号设置（Gitee/GitHub/Vercel）、轮换或删除凭据、删库或回滚版本、改点歌平台的 CORS 白名单 | **先问，你点头再做** |

**绝对不要给 AI 的东西**（如果它主动索要，直接拒绝）：

- Gitee / GitHub 的**账号密码**
- 长期有效的 access token（真有必要给，**用完立刻去删掉重建**）
- 点歌平台的 **API key 明文**（页面里存的是混淆密文、运行时才解密，这个设计必须保持）
- 导出备份包的**解压密码**

### 3.3 开场白模板（直接复制整段发给新 AI）

```
你在维护「25级05班 班级服务站」这个静态 PWA 站点。

【基本情况】
- 唯一内容源（git）：Gitee 仓库 zikang0529/class-site，分支 master
- 主链：https://yuzikaaang.github.io/class-site/
  （由 Gitee 镜像自动同步到 GitHub Pages，push 后自动刷新，不需要手动同步）
- 备用链接：https://a5048c773a210b3d4-25579.app.workbuddy.link/
  （每次内容改完需要重新发布；微信内打不开）
- 结构：单文件 PWA —— index.html + games/*.html（13 个小游戏）+ sw.js

【开工前必读】
先读这两个文件，它们包含了全部站规、历史变更和踩过的坑，读完再动手：
1. internal/notes.md  —— 站规 / 铁律 / 运维备忘 / 历史变更台账
2. internal/guide.md  —— 站主操作教程

【硬性要求】
- 改完必须本地起服务跑测试验证，不能只靠"看代码觉得没问题"
- 改完按站规同步：站内公告 + internal/notes.md + 重打包备份 + 重新发布备用链接
- 亮色 / 暗色双模式下，所有文字都要达 WCAG AA（正文 4.5:1，大字号 3:1）
- 汇报时必须分开写「✅ 已验证（列出测试名和通过数）」和
  「⚠️ 无法验证、需要我自己确认的」，不要假装验过
- 涉及我的账号设置、凭据、删数据、回滚 —— 先问我，不要自作主张
- 不要向我要账号密码或长期 token；需要推代码就用 SSH 公钥

【本次要做的事】
（在这里写你的具体需求）
```

### 3.4 验收：要求它交两份清单

每次让 AI 改完，让它按这个格式汇报。如果它只说「已完成」，就追问一句「哪些是实测过的？哪些你访问不到？」

```
✅ 已验证：
   - test_xxx.py  29 项全过
   - 全站对比度扫描 591 个文字元素，亮暗双模式 0 不达标
⚠️ 需要你自己确认：
   - 主链 GitHub Pages 内容（本环境连不上 GitHub，无法验证）
   - 真机微信内打开效果
```

**这条最有用**：本环境连不上 `github.io` 和备用链接域名，所以凡是「主链对不对」这类事，AI 都验不了 —— 它必须老老实实说验不了，而不是含糊过关。

### 3.5 结束合作时回收权限

1. 去 `https://gitee.com/profile/sshkeys` 删掉那个环境加的公钥（title 里带环境名，比如 `class-site-sandbox-20260829`）
2. 如果中途给过 token，去 `https://gitee.com/profile/personal_access_tokens` 删掉重建
3. 确认 `internal/notes.md` 最后一条更新记录写完整了 —— **下一位 AI 全靠它接手**

## 4. 其他常见操作

### 4.1 换域名后要加 CORS 白名单

点歌平台是**你自己的 fork 仓库 `yuzikaaang/VoiceHub`**，白名单**硬编码**在源码里（没有环境变量可配）：

1. 打开 `yuzikaaang/VoiceHub` → 文件 `server/middleware/api-0-open-cors.ts`
2. 在 `ALLOWED_ORIGINS` 这个 Set 里加一行，例如 `'https://新域名'`
3. 提交到 `main` 分支 → Vercel 自动部署

**匹配规则（已实测）**：精确匹配 **协议 + 主机 + 端口**，**末尾不能带斜杠**。

验证是否生效（不用浏览器，一条命令）：

```bash
curl -i -X OPTIONS 'https://xsyzc2505.dpdns.org/api/open/songs' \
  -H 'Origin: https://你的域名' \
  -H 'Access-Control-Request-Method: GET' \
  -H 'Access-Control-Request-Headers: x-api-key'
```

看到 `access-control-allow-origin: https://你的域名` 就是成功了。

### 4.2 需要读 `secrets.json.enc` 里的令牌

> ⚠️ 旧文档里写的 `./scripts/decrypt-secret.sh` 和 `secrets-hint.txt` **早已删除**，别再找了。

- 文件是 OpenSSL 加密的二进制密文，密码是**你自己设的 6 位数字**
- 需要用时让 AI 现场写命令解密，**密码你自己输、不要让 AI 记录明文**
- 忘了密码：里面的内容（Gitee/GitHub 令牌）都可以去各自平台重新生成，**不影响站点运行**

### 4.3 备份与还原

- **备份**：站点「数据管理 → 导出备份」，会存一份到浏览器下载
- **仓库快照**：`class-site-backup.zip`（每次改完 AI 会重打；**不含** `internal/`）
- **还原**：在 Gitee 上找到对应提交 → 回滚；或让 AI 从 `backup/` 目录里找历史包

### 4.4 备用链接失效了

沙箱会话结束后链接可能失效。让 AI 重新发布一次即可（站规：push 后自动重发，不用你开口要）。

## 5. 出问题速查

| 现象 | 大概率原因 | 怎么办 |
|---|---|---|
| 主链内容没更新 | 镜像同步延迟 | 等 5 分钟；超时去 Gitee「仓库镜像管理」手动同步 |
| 备用链接打不开 | 沙箱会话结束 | 让 AI 重新发布 |
| 备用链接在微信里白屏 | 微信内置浏览器限制 | 复制链接到系统浏览器打开 |
| 抽签提示「连不上点歌平台」 | CORS 白名单没配、或 API 真挂了 | 见 4.1；主链正常就说明是备用域名没加白名单 |
| 备份包下载失败（`.zip` 403） | 备用域名前置 WAF **按后缀封禁 `.zip`** | 站点已内置回退（会自动取无扩展名副本），重试即可 |
| AI 说推不了代码 | SSH 公钥被删了 | 让它重新生成密钥对，加新公钥到 `https://gitee.com/profile/sshkeys` |
| 页面显示旧内容 | Service Worker 缓存 | 硬刷新；SW 是网络优先，一般自动更新 |
